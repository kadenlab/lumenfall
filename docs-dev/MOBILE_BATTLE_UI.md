## 原因と今回の変更

スマホCSSが右下の独立コマンド、左下の味方パネル、絶対位置のログを個別に配置し、試練・灯路切替の高さ指定も重複していた。また「港へ戻る」等はDOMだけでなく3D背景内の案内看板にも描かれており、戦闘中も表示が続いていた。Chapter固有モーダルの共通描画にも戦闘状態による抑止がなかった。

UI変更は `app/game.ts` と `app/globals.css`。既存設計に合わせて幅600px以下に適用。

- 敵情報／中央フィールド／下部戦闘領域の3段構成。
- 下部に名前・Lv・HP/MP、行動ログ、基本6コマンドを配置。ログはコマンド領域の見出しを兼ねる。
- 基本コマンドは2列×3段、48px以上（高さ700px以下では44px以上）。追加コマンドはその下に3列の行を設け、削除しない。
- 敵名・現在HP・HPバー・予告をコンパクト化。試練の敵選択、灯ゲージ、既存の情報隠蔽ルールは維持。
- `env(safe-area-inset-top/bottom/left/right)` を使用。既存の `viewport-fit=cover` を維持。
- モバイルでは実測した上下パネル間にカメラの表示中心を合わせる。短い画面ではカメラ距離も調整し、キャラクターの見える大きさを確保。戦闘中の移動・攻撃・演出ロジックは変更しない。
- 共通の `mode === 'battle'` で探索モーダルと探索通知を描画しない。探索HUD、目的地、マップ、メニュー、調べる、移動スティックは既存のモード分岐でDOMに存在しない。
- 3Dの移動看板と移動リングを探索用としてマークし、戦闘中は非表示、終了後は再表示。看板に独自のクリック判定はなく、背景タップも既存の戦闘状態チェックで移動しない。
- PCでは新ラッパーを `display:contents` とし、既存の絶対位置とカメラを維持。

セーブ形式・保存キーは変更なし。検証ではDEBUG専用セーブを使用。

## ZIPをGitHubへ反映する手順

ZIPにはリポジトリ直下からのファイルを収録しています（外側フォルダ、node_modules、.git、検証用セーブなし）。GitHubそのものへのアップロード／公開はこの作業では実行していません。

1. `kadenlab/lumenfall` のチェックアウトへZIPの中身を上書きします。
2. リポジトリ直下で `node scripts/remove-obsolete-docs-assets.mjs` を実行します。今回の基準mainにあった不要60ファイルだけを名前・SHA256で確認して削除します。内容が異なるファイルはエラーにして削除しません。
3. `git add -A` で更新・新規・削除をすべてステージし、差分を確認してコミット／pushします。Pages公開元は `/docs` を維持します。

GitHubのWeb画面でアップロードする場合もZIPそのものを置くのではなく、中身を展開して反映してください。Webの上書きは削除を反映しないので、`docs-dev/OBSOLETE_DOCS_ASSETS.json` に列挙した60ファイルを削除し、`docs/assets` が新しい67ファイルだけになるようにします。ローカルチェックアウトで上記スクリプトを使う方法が確実です。`docs/index.html` と新assetsは同じ更新に含めてください。
