# 最適化・検証記録

## CPU / GC

- near判定は距離の二乗を比較する単純ループ（前回最適化済み）。filter/sortは使用しない。
- 毎フレームの位置補間・lookAtは外側のVector3を再利用（前回最適化済み）。
- fxは逆順で元配列を処理（前回最適化済み）。
- 毎フレーム生成していた `[hero, companion]` を2回の関数呼び出しに置換。
- Chapter 1移行用の状態ビューはWeakMapで再利用。封印一覧もフラグ変更時だけ作り直す。経路探索で一時Proxy/配列を大量生成しない。
- 同一UI文字列の再構築後DOM更新抑制、静的背景のまとめ描画、非表示タブ停止、タイマー解除を維持。

## GPU

- 噴水(2.4×2.4)のReflectorを廃止。川の384×384反射は維持。噴水は通常のライティング・波・色付き半透明面で表現。
- 水面の分割をサイズ別に設定。噴水は429→16頂点（768→18三角形）。川は429頂点を維持。
- 水面は既にGPUシェーダーで波と法線を計算し、CPUの頂点更新/computeVertexNormalsは存在しない。CPU処理を戻さず、波の時刻だけ2描画フレームに1回更新（60fpsなら約30Hz）。
- スマホpixel ratioは最大1.2、PCは従来通り1.25。画素数予算・自動画質を維持。
- スマホはPCFShadowMap、PCはPCFSoftShadowMap。影解像度は既に1024なので維持。屋外の更新は最大2Hz、遺跡は静的再利用。
- Bloom・ティルトシフト・霧密度・主要な色味・ライト数制限・魔法演出を維持。

## 見た目への影響

噴水に背景の鏡像は映らなくなります。水色、波、照明は残ります。スマホでは影の縁が少し硬くなる場合があります。川やボスの発光、霧、カメラ、ヒットストップは維持します。水面アニメーションのみ更新頻度を半分にしています。

## 残る確認限界・ボトルネック

検証ブラウザはWebGLが無効で、実プレイはCanvas互換描画です。実機GPUの60fps、Bloom・影・水反射のGPU上の最終描画は未確認です。GPU設定・数値とビルドは検証済みですが、実機での差分確認が必要です。

共通Three.js/ポストエフェクトのJavaScriptは約608kB（gzip約160kB）で、Viteの500kB警告が残ります。描画フレーム負荷とは別の初回ロード負荷です。大きな川の反射、影、全画面ポストエフェクトは残るGPUコストです。互換描画はCPUラスタライズのため、大きな画面ではWebGLより遅くなります。

最終再開時はnpmラッパーの再実行が環境側で中断されたため、同じスクリプトを直接実行しました。`node --test tests/*.test.mjs` は16件成功、`node scripts/build.mjs` は成功。先のCPU/GPU各段階のnpm test / npm run buildも成功済みです。
